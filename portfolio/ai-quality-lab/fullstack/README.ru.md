# AI Quality Lab · React / TypeScript + FastAPI

[Deutsch](README.md) · [English](README.en.md) · [Публичная Worker-демонстрация](https://ai-quality-lab-neta26.wellolm4.chatgpt.site)

Отдельная запускаемая реализация того же учебного проекта: React-интерфейс, типизированные HTTP-запросы, сервер Python/FastAPI и общий проверяющий модуль. Эта папка содержит локальную React/Python-версию; публичный сайт продолжает работать на Worker.

## Запуск

Нужны Node.js 22.12+ или 24+, Python 3.12. Из скачанного репозитория:

~~~sh
cd portfolio/ai-quality-lab/fullstack
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
cd frontend
npm ci
npm run build
npm test
cd ..
.venv/bin/python -m pytest tests -q
.venv/bin/uvicorn backend.app:app --host 127.0.0.1 --port 8000
~~~

Откройте **http://127.0.0.1:8000**. Проверка примеров, редактирование и экспорт работают без ключа API. Интерактивная документация API: **http://127.0.0.1:8000/docs**.

В Windows для создания окружения используйте `python`, затем `.venv\Scripts\python.exe` и `.venv\Scripts\uvicorn.exe` вместо путей с `bin/`. Для разработки в отдельном терминале из папки `frontend` выполните `npm run dev`: Vite перенаправляет запросы `/api` в локальный FastAPI.

## Что реализовано

Восемь фиксированных немецких заданий, выбор случаев, два редактируемых ответа, серверная проверка правил, взвешенные оценки и скачивание отчёта. Четыре языка интерфейса, немецкий при первом запуске. Есть необязательный адаптер Responses API: после ручного изменения текста отметка о происхождении от модели снимается.

## Реальная модель

По умолчанию выключена. Нужны четыре серверные переменные из `.env.example`: `QUALITY_LAB_ENABLE_LIVE=true`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `QUALITY_LAB_GENERATION_TOKEN`. Последняя — отдельный случайный код доступа длиной от 32 символов, а не ключ OpenAI.

Переменные задаются в окружении сервера или в менеджере секретов, после чего сервер перезапускается. Файл `.env` автоматически не читается. Ключ провайдера не передаётся в браузер; код доступа хранится только в памяти открытого клиента.

На `https://api.openai.com/v1/responses` отправляется только выбранное учебное задание. У A короткая инструкция, у B более подробная; модель одна и та же. Нет инструментов, свободного прокси и автоматических повторов. Указаны `store: false` и ограничение `max_output_tokens: 512`; это не обещание полного отсутствия хранения у провайдера.

По умолчанию разрешено 20 попыток в час на процесс, включая ошибки. Перезапуск и несколько процессов имеют отдельные счётчики. Финансовый лимит нужно дополнительно установить в API-проекте. Реальные вызовы могут расходовать средства.

## API и отчёт

`GET /api/config` показывает готовность подключения без секретов, `GET /api/cases` — тестовые задания, `POST /api/evaluate` — проверяет ответы, `POST /api/generate` — вызывает модель после проверки заголовка `X-Generation-Token`.

Отчёт содержит подтверждения генерации только для неизменённых ответов, участвовавших в проверке. Проверяющий модуль сам модель не вызывает. Сервер не сохраняет введённые тексты. Это локальный пример: для публичного размещения нужны управляемая авторизация и постоянный распределённый учёт лимита.

## Проверки

Прошли **17 проверок API и 8 проверок клиента**, проверка TypeScript и производственная сборка. Контракт провайдера, таймауты, ошибки, доступ, лимиты и происхождение ответов проверяются через имитацию HTTP-провайдера. **Настоящий запрос к модели ещё не проверен.** Сборка Docker и визуальная проверка браузера/телефона не выполнены.
