# Самостоятельный проект: статистика на Python и SQLite

Автор проекта: Natalie Ragulina (Netaniya). © 2026. Учебные материалы, разработанные с помощью ИИ.

## Цель

Реализовать три функции слоя данных реального приложения без готового решения. Используется Python 3, стандартный модуль sqlite3, временная база в памяти. Не нужен интернет, пароль или внешний сервер. Используй только вымышленные записи.

## 1. Подготовка

Открой терминал в каталоге fullstack-lab. Проверь python3 --version (Windows: py -3 --version). Запусти эталонные проверки:

    python3 check_dashboard.py

Открой learner_dashboard.py. Запусти:

    python3 check_dashboard.py --learner

Изначально проверки намеренно не пройдут. Не изменяй тесты, чтобы получить зелёный результат.

## 2. Прочитай схему

projects(id INTEGER PRIMARY KEY, title TEXT NOT NULL, done INTEGER NOT NULL CHECK(done IN (0,1))).

Строка — проект. done=0 означает открыт, done=1 завершён. db — уже открытое соединение SQLite. SQL исполняется через db.execute. fetchone возвращает одну строку, fetchall — все строки. COUNT(*) считает строки; SUM(done) суммирует флаги. На пустом наборе SUM возвращает NULL: изучи COALESCE.

## 3. Напиши собственные функции

- summary(db): вернуть словарь total, done, open. Обработать пустой набор.
- open_projects(db): вернуть пары (id, title) для открытых проектов, отсортированные по id.
- complete(db, ident): завершить одну запись по положительному целому id, вернуть True, если запись существует. bool, числа вне диапазона SQLite INTEGER (2^63−1), дроби, строки и неизвестный id возвращают False. Используй параметр ? и кортеж (ident,), а не склеивание SQL. Не делай commit и не закрывай db: транзакцией управляет вызывающий код.

## 4. Самопроверка

Запускай python3 check_dashboard.py --learner после каждой функции. Тесты проверяют пустой набор, сортировку, изменения, повторное завершение, некорректные аргументы, откат транзакции и строки с Unicode/SQL-пунктуацией. Добавь собственный пример с тремя проектами, предскажи результат, затем выполни тест. Сравни с dashboard_reference.py только после самостоятельной попытки.

## 5. Связь с полноценным приложением

В server.py уже есть реальный HTTP-сервис с классом Store, в app.js — клиентские fetch-запросы. Сравни свои функции с реализацией Store.stats/update. Запусти существующую лабораторию по README.md, создай проект, заверши его, обнови страницу и перезапусти сервер. Твоя работа здесь — самостоятельный слой данных; подключение ученического модуля в HTTP-сервис пока выполняется вручную, не автоматически. Это локальное обучение, не производственное размещение.
