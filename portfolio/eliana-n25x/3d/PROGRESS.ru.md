## Что реализовано

Three.js r160 хранится локально с MIT-лицензией. Настоящие объёмные модели Eliana и N25x имеют иерархию суставов и анимации ожидания, ходьбы, бега и работы. Модели предварительные, не фотоскан и не обещание точного сходства. Каштановые длинные волосы и светлая куртка Eliana, белые панели и тёмная лицевая поверхность N25x соответствуют направлению исходных портретов.

WASD/стрелки, Shift, E, Esc/P, камера перетаскиванием мыши, приближение колёсиком. Для телефона — джойстик, отдельный указатель камеры и кнопки. Есть столкновения с геометрией, включая стены, постаменты, лабораторные столы и обломки, ограниченная поверхность, камера с проверкой стен, обход препятствий роботом. Все шесть компактных районов используют общую основу: сообщение → три компонента/устройства → физическое прибытие N25x и сканирование → ремонт → поднимающиеся ворота → проход игрока → очки и следующий район. Финал после шестого района.

Четыре языка, первый вход на немецком; спокойный режим и бонус за скорость; звуки, шаги, фон, громкость и отключение; пауза; автоматическое сохранение и импорт/экспорт. Новый ключ `eliana-n25x.3d.v1` не изменяет старый `eliana-n25x.save.v1`.

Отдельный manifest и service worker. Все 15 необходимых файлов сверяются с SHA-256 перед сообщением об офлайн-готовности. Сборщик не публикует исходники тестов и зависимости разработки. Общая сборка дополнена только копированием результата 3D-сборки.

В следующем запуске `38881865525` независимая мобильная проверка уже прошла: два реальных CDP-касания в эмуляции 390×844 двигают персонажа и камеру одновременно без прокрутки, органы управления видны и в 844×390. ## Как продолжать

1. Проверить свежую `main` и запуск workflow **Eliana 3D browser playthrough**. Тесты находятся в `3d/browser-tests/run.mjs`; это настоящий браузер с реальными клавишами, мышью и CDP-касаниями. Они не подменяют WebGL, не телепортируют героев и не меняют состояние миссии.
2. При ошибке получить логи job и артефакт `eliana-3d-browser-evidence`. В нём `verification.json`, фактический скриншот ошибки и видеозапись. Исправить наблюдаемую причину, сохранить коммит, дождаться нового результата.
3. Обязательно довести первую миссию до выхода за открытые ворота, затем проверить шесть миссий и финал, очки 2100 в спокойном режиме, офлайн-перезагрузку после первого района и мобильные два касания.
4. После успеха сохранить отчёт о проверках и реальные скриншоты в репозитории; дать владельцу ссылку на 3D-игру. Обновить вход из портфолио/старого квеста, сохранив старую игру. Не называть графику фотореалистичной.
5. Обновить этот файл подтверждёнными результатами и ссылками. Не обещать продолжение фоновой работы после завершения чата.

## Сборка

```sh
npm ci --ignore-scripts --prefix portfolio/eliana-n25x
npm ci --ignore-scripts --prefix portfolio/motion-atelier
node scripts/build-pages.mjs
npm run check --prefix portfolio/eliana-n25x
npm test --prefix portfolio/eliana-n25x
node --test tests/pages.test.mjs
```

На GitHub Actions отдельный workflow с независимыми заданиями `desktop` и `touch` устанавливает закреплённый Playwright 1.62.1 и официальный Chromium с программным WebGL, собирает `3d/dist` и запускает `3d/browser-tests/run.mjs`. Документационные коммиты не запускают тяжёлое браузерное прохождение повторно. Секреты и платные API не используются.

В текущем окружении git-сеть до github.com была недоступна, но GitHub connector подтвердил доступ на запись. Файлы сохранялись через `create_tree` → `create_commit` → `update_ref` с проверкой `expected_sha`, сохраняя полное дерево репозитория. Локальный git — рабочий снимок, его SHA не равен удалённому. Для удалённых родителей использовать SHA из GitHub.

Основные сохранённые удалённые этапы: `eaeefcf` (изолированная 3D-версия), `e66f257` (браузерная проверка), `d6ef333` (независимость скорости от кадров), `1bd7e99` (материалы героев и наблюдение реального ввода). Последующие коммиты смотреть в GitHub; этот список не заменяет проверку актуальной ветки.
